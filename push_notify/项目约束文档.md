## 一、项目概述

### 1.1 产品定位
校园二手交易信息聚合搜索工具。采集QQ二手交易群的消息，自动分类、提取关键信息，提供模糊搜索和物品订阅提醒功能。

### 1.2 目标用户
- **采集端**：产品负责人（用户wff），在自己电脑上运行采集程序，监听10-20个校园二手QQ群
- **查看端**：校园内其他同学，通过手机浏览器/PWA访问搜索页面，零安装

### 1.3 核心价值
解决校园二手群信息淹没在聊天记录中、找东西效率低的问题。将分散在十几个群里的二手信息聚合，一键搜索+订阅提醒。

### 3.2 数据流

```
QQ群消息 → NapCat WebSocket → run.py 接收
  → 保存原始JSONL到 messages/raw/
  → 每5条或30秒触发 preprocess.py
    → 合并同用户消息（60s窗口）
    → 过滤表情包
    → 拆分多商品消息
    → 分类（出售/求购/通知/待OCR/闲聊）
    → 实体抽取（物品名/价格/成色）
    → 联系方式提取
    → OCR（如已安装）
    → 输出 ready_to_label.jsonl
    → 生成 review.html
  → HTTP服务提供访问
```

## 五、技术约束与限制

### 5.1 不可逾越的约束

| 约束 | 原因 | 影响 |
|------|------|------|
| NapCat只能在Windows桌面运行 | 通过DLL注入NTQQ进程 | 手机端无法直接采集QQ消息 |
| QQ不开放群消息读取API | 官方机器人只能读@它的消息 | 无法通过官方API获取所有群消息 |
| iOS完全隔离 | 沙箱不允许读其他App通知 | iOS无法做消息采集 |
| 电脑睡眠=服务停止 | CPU停止、网络断开 | 需设置不睡眠或用云服务器 |
| 校园网客户端隔离 | 同WiFi设备间不能通信 | 需手机热点或内网穿透 |

### 5.2 可优化的约束

| 约束 | 当前状态 | 优化方向 |
|------|---------|---------|
| 分类用关键词规则 | 误判率约10% | 标注500条后训练BERT |
| 搜索用字词模糊匹配 | 有噪音 | sentence-transformers词向量 |
| 图片未OCR | 91条待OCR | 安装PaddleOCR |
| 仅局域网访问 | 同WiFi可用 | cpolar/腾讯云 |
| 手动刷新HTML | 新消息需F5 | WebSocket推送或定时刷新 |

### 5.3 合规约束

| 约束 | 说明 |
|------|------|
| 不破解QQ安全机制 | 违反腾讯协议，可能封号+法律风险 |
| 不逆向QQ协议 | 同上，且技术风险极高 |
| NapCat属于灰色地带 | 基于NTQQ的第三方框架，腾讯未明确禁止但也不支持 |
| 数据仅本地存储 | 不上传用户隐私到第三方服务器 |

## 六、关键决策记录

### 6.1 为什么选NapCat而不是官方机器人

| 维度 | NapCat | QQ官方机器人 |
|------|--------|-------------|
| 读取群消息 | 全部消息 | 仅@机器人的消息 |
| 部署方式 | 本地Windows | 云端注册 |
| 合规性 | 灰色地带 | 完全合规 |
| 功能限制 | 无 | 主动推送已被限制 |

**决策**：选择NapCat，因为核心需求是"读取所有群消息"，官方机器人无法满足。

### 6.2 为什么选PWA而不是原生App/QQ小程序

| 维度 | PWA | QQ小程序 | 原生APK |
|------|-----|---------|---------|
| 开发量 | 加2个文件 | 重写后端 | 重写全部 |
| 用户安装 | 添加到桌面 | QQ内搜索 | 下载APK |
| 跨平台 | 安卓+iOS+桌面 | 仅QQ内 | 仅安卓 |
| 审核流程 | 无 | 需腾讯审核 | 需商店审核 |

**决策**：选择PWA，最快实现"像App一样"的体验，无需审核。

### 6.3 为什么采集端在电脑而不是手机

- NapCat通过DLL注入NTQQ桌面客户端，手机上不可能运行
- iOS沙箱完全隔离，无法读取QQ通知
- Android的NotificationListenerService可读通知但会截断+无法读图片
- 电脑采集+手机查看是当前最可行的架构

### 6.4 关于手机端独立App的讨论结论

用户希望做成"每人下载App就能采集自己QQ消息"的产品。经调研：
- 安卓可通过NotificationListenerService监听QQ通知（合法，无需Root）
- 但只能读通知栏截断内容，无法读图片
- iOS完全不可能
- 这条路径可作为后续Android版本的方向，当前优先桌面+PWA方案

### 10.4 图片路径规范（重要）

**规则**：HTML中的img标签必须使用绝对路径（从根目录开始），不能用相对路径。

| 维度 | 规范 |
|------|------|
| 路径格式 | `/messages/images/{group_id}/{filename}.jpg` |
| 禁止 | `../images/...`（相对路径在JSON数据中解析不可靠） |
| 禁止 | `images\458644002\...`（Windows反斜杠，浏览器无法解析） |
| onerror | `onerror='this.style.display="none"'`（图片加载失败时隐藏，不显示破图） |
| Service Worker | 图片请求不走缓存（避免缓存404响应），见 `sw.js` |
